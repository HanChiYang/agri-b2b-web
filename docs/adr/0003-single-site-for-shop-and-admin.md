# ADR-0003：前台和後台做成同一個網站

- 狀態：已接受
- 日期：2026-10-25

## 背景

平台有三種使用者：訪客（公司簡介）、經銷商（瀏覽商品、下單）、管理員（後台）。後端的 ADR-0001 留下「前台和後台要做成一個網站還是兩個」的問題。

## 決策

- 做成一個 Angular 網站
- 後台放在 `/admin/**` 底下，用 lazy loading 載入，經銷商不會下載到後台的程式
- 用 route guard 依角色擋下不能進的頁面；權限仍然由後端把關

## 考慮過的其他方案

- 前台和後台分成兩個 Angular app（同一個 workspace 或兩個 repo）：後台的程式完全不會出現在經銷商的網站，也能分開部署；但登入、API client、錯誤處理、共用元件要放成共用的 library，建置、CI、部署都變成兩份。一人開發的專案，代價大於好處

## 影響

- 登入、API client、錯誤處理、共用元件都只有一份，部署一個網站
- 後台的程式碼放在同一個網站的 JS 檔裡，有心人可以下載來看。後台頁面本身不含機密，所有資料和操作都要經過後端的權限檢查，所以可以接受；前端不能放任何只有管理員該知道的資料
- 之後如果後台要另外部署（例如只開放公司內網），再把 `/admin` 拆成獨立的 app，寫一份新的 ADR
