# ADR-0004：前端放在獨立的 repo

- 狀態：已接受
- 日期：2026-10-25

## 背景

後端在 GitHub repo `agri-b2b-platform`。前端可以放進同一個 repo（例如 `web/` 資料夾），也可以另外開一個。

## 決策

- 前端放在獨立的 repo：`agri-b2b-web`
- 後端仍是 API 的唯一依據：前端的 API 型別從後端的 OpenAPI 文件產生，不手寫

## 考慮過的其他方案

- 放進後端的 repo：API 和畫面的修改可以放在同一個 PR，產生型別也比較方便；但 .NET 和 Node 的建置、CI、hook、規格流程要寫在同一個 repo 裡分開處理，後端現有的 hook（例如只擋 `src/`、`tests/`）和 CI 都要改

## 影響

- 兩個 repo 各自有自己的 `CLAUDE.md`、規格、ADR、CI，流程互不干擾
- API 改了，前端要重新產生型別才會發現不一致。前端需要後端改的地方，記在 `docs/plan.md` 第 6 節，交給後端的流程處理，不在前端的工作中修改後端
- 前後端的版本要自己對齊：前端的每個階段寫明需要後端的哪個階段
